# Мини-карточка лида (тестовое CRM)

Одна веб-страница: форма добавления лида, валидация, список карточек и сохранение в `localStorage`.

## Как открыть

Вариант 1 — просто открыть файл:

```bash
open lead-card/index.html
```

Вариант 2 — локальный сервер:

```bash
npx --yes serve lead-card
```

## Что сделано по ТЗ

- [x] Поля: имя, телефон, источник (Холодный/Тёплый), ответственный (Лидоруб/МОП), этап сделки (4 значения), переключатель «Запрошено ТЗ», кнопка «Сохранить»
- [x] Проверка обязательных полей (имя + телефон) с сообщением об ошибке
- [x] Лид появляется ниже в виде карточки со всеми данными
- [x] Данные не пропадают после обновления страницы (`localStorage`, ключ `crm_mini_leads`)
- [x] **Дополнительно:** изменение этапа сделки прямо в карточке

## Где что в коде (`index.html`)

| Часть | Где смотреть |
|-------|----------------|
| **Интерфейс** | HTML-форма `#lead-form` + CSS-блок «ИНТЕРФЕЙС»; отрисовка списка — функция `renderLeads` |
| **Логика кнопки** | Обработчик `form.addEventListener("submit", …)` — блок «ЛОГИКА КНОПКИ» |
| **Сохранение данных** | `loadLeads` / `saveLeads` + `localStorage` — блок «СОХРАНЕНИЕ ДАННЫХ» |
| **Смена этапа** | Слушатель `change` на `#leads-list` — блок «ДОПОЛНИТЕЛЬНО» |

Комментарии в файле помечены так же: `ИНТЕРФЕЙС`, `ЛОГИКА КНОПКИ`, `СОХРАНЕНИЕ ДАННЫХ`.

## Что проверить на демо

1. Открыть страницу
2. Нажать «Сохранить» без имени/телефона → ошибка
3. Заполнить форму → карточка появляется
4. Обновить страницу (F5) → лид на месте
5. В карточке сменить этап → значение обновляется и тоже сохраняется после F5
